## 1. Investigacion y fix del /grafiti

**Problema reportado:** Jugadores de facciones ilegales no podian usar /grafiti.

**Causa:** El tag `FAC_TAG_ALLOW_GRAFITI` no estaba activado en la faccion. El comando verifica ese flag antes de cualquier otra cosa. Sin el flag, bloquea a todos los miembros sin importar el rango.

**Solucion:** No requirio cambio de codigo. El tag se activa desde el panel de administracion de facciones:
- Comando `/af` (o `/af [id]`) â†’ seleccionar la faccion â†’ modificar flags â†’ activar "Puede hacer grafitis"

**Informacion adicional relevante:**
- Item ID de la lata de spray: `41` (`ITEM_ID_SPRAYCAN`)
- Comando para dar items: `/aitemdar [ID jugador] 41 1` (requiere admin nivel 14)
- El rango que puede usar /grafiti es <= 3 (verificado consistente entre marp_grafitis.pwn y marp_core.pwn)

### Tabla SQL

```sql
CREATE TABLE IF NOT EXISTS `twitter` (
    `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `pID`        INT UNSIGNED NOT NULL,
    `pName`      VARCHAR(24)  NOT NULL DEFAULT '',
    `username`   VARCHAR(20)  NOT NULL,
    `created_at` TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    UNIQUE KEY `uq_pID`      (`pID`),
    UNIQUE KEY `uq_username` (`username`)
) ENGINE=InnoDB DEFAULT CHARSET=latin1;
```

Requiere ejecucion manual en la DB antes de usar el sistema.

### Comandos de jugador

| Comando | Requisito | Descripcion |
|---|---|---|
| `/registrarsetwitter` | Sin cuenta previa | Abre dialog para elegir @username unico (3-20 chars, alfanumerico + _). Solo se puede registrar una vez por personaje. |
| `/activartwitter` | Tener cuenta | Conecta al jugador a Twitter. Empieza a ver y enviar mensajes. |
| `/desactivartwitter` | Twitter activo | Desconecta al jugador. Deja de ver mensajes. |
| `/tw [mensaje]` | Twitter activo | Envia tweet visible para todos los jugadores con Twitter activo. Max 128 chars. Cooldown configurable (default 3 min). |
| `/ayudatwitter` | Cualquiera | Muestra los 4 comandos disponibles en azul Twitter. |

### Comportamiento

- Al conectarse, se carga el username desde DB automaticamente via hook `LoadAccountDataEnded`
- Al desconectarse, se resetea el estado en memoria (active, lastmsg)
- Los mensajes aparecen en color Twitter blue (`0x1DA1F2FF`) con formato `[Twitter] @username: mensaje`
- Solo los jugadores con Twitter activo ven los mensajes

### Comando de administracion

**`/cooldowntwitter`** â€” nivel 3 (Helper) o superior

Abre un dialog lista con las opciones:
1. Sin cooldown
2. 30 segundos por mensaje
3. 1 minuto por mensaje
4. 3 minutos por mensaje (valor por defecto al iniciar el servidor)
5. 5 minutos por mensaje
6. Deshabilitar Twitter (nadie puede enviar mensajes)

Al aplicar cualquier opcion, se notifica a todos los jugadores conectados con el nuevo estado. El titulo del dialog muestra el cooldown actual y si Twitter esta habilitado o deshabilitado.

El cooldown y el estado de habilitacion son variables en memoria â€” se resetean al reiniciar el servidor (vuelven al default: 3 minutos, habilitado).

## 4. Ajustes post-implementacion al sistema de Twitter

### Requisito de telefono

Se agrego como requisito para usar `/tw` que el jugador tenga un telefono comprado (campo `pPhoneNumber != 0`).

Si no tiene telefono, el mensaje es:
> `[INFO] ¿Cómo querés usar Twitter si no tenés un teléfono, pavo? Comprálo en el 24-7.`

El check se hace antes de cualquier otra validacion (cuenta, activacion, cooldown).

### Correccion de colores

Se unificaron los colores del sistema:

| Mensaje | Color anterior | Color nuevo |
|---|---|---|
| Cuenta creada | `COLOR_INFO` (violeta) | `TWITTER_COLOR` (azul) |
| Cambios de cooldown por admin | `COLOR_INFO` (violeta) | `TWITTER_COLOR` (azul) |
| Conectado / desconectado | `COLOR_INFO` (violeta) | `TWITTER_COLOR` (azul) |
| Twitter deshabilitado por admin | `COLOR_INFO` (violeta) | `TWITTER_COLOR` azul con prefijo `{FF0000}[Twitter]` en rojo |
| `/ayudatwitter` | `TWITTER_COLOR` (azul) | `COLOR_INFO` (violeta del servidor) |

### Visibilidad de tweets

Solo reciben los mensajes de `/tw` los jugadores que tienen Twitter activo (`TwitterActive[i] == true`). Requiere haber hecho `/registrarsetwitter` + `/activartwitter`. Sin esas dos acciones, los mensajes no aparecen.

## 6. Sistema /cadera - Configuracion de modo

Se agrego el subcomando `/cadera configuracion` que abre un dialog con dos opciones:

| Opcion | Comportamiento | Hueso |
|---|---|---|
| Con movimiento (recomendada para la pierna) | Se mueve con la pierna al caminar | `ATTACH_BONE_ID_RIGHT_THIGH` (8) |
| Sin movimiento (recomendado: cintura/pecho) | Estatico, no sigue animaciones | `ATTACH_BONE_ID_SPINE` (1) |

Al seleccionar una opcion, la posicion se resetea a los valores por defecto del modo y el arma se reposiciona automaticamente. El modo se guarda en la DB y persiste entre sesiones.

### SQL requerido

Se agrego la columna `mode` a la tabla `holster` via archivo `database/holster_mode.sql`:

```sql
ALTER TABLE `holster` ADD COLUMN `mode` TINYINT UNSIGNED NOT NULL DEFAULT 0;
```

**Importante:** Este ALTER TABLE debe ejecutarse ANTES de reiniciar el servidor con el nuevo codigo. Si no se ejecuta, el SELECT de carga del holster falla (`Unknown column 'mode'`) y el arma guardada en la cadera no se carga en memoria, aunque los datos en la DB no se pierden.

El `DEFAULT 0` garantiza que los registros existentes queden en modo 0 (con movimiento, comportamiento original) sin necesidad de migracion de datos.

**Regla general para futuros ALTER TABLE:** Siempre ejecutar el SQL antes de hacer deploy del codigo que lo requiere. Si se hace al reves, las queries fallan silenciosamente hasta que se aplique el ALTER.
