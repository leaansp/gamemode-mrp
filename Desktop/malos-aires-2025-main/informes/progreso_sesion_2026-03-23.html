Limitación SA-MP documentada

Alt, Shift y combos NO funcionan en vehículo vía OnPlayerKeyStateChange.
Solo disparan en vehículo: KEY_NO (N), KEY_YES (Y), KEY_CROUCH (C), KEY_SUBMISSION (Numpad2).
Por eso luces y puertas del vehículo no tienen hotkey — se usan los comandos /vehluces y /vehpuertas.

2. Sistema de Funda de Cadera (/cadera) EN PROGRESO — pendiente testeo

Descripción

Sistema que permite a los jugadores guardar armas cortas (pistolas, subfusiles compactos) en la cadera con representación visual mediante SetPlayerAttachedObject en el hueso del muslo derecho (ATTACH_BONE_ID_RIGHT_THIGH = 8). El arma persiste entre relogueos vía MySQL. La posición del attachment es editable por cada jugador individualmente con /cadera editar.

3. Base de datos

Tabla nueva: holster

Una fila por jugador (PRIMARY KEY = playerid de la tabla accounts). Se usa INSERT … ON DUPLICATE KEY UPDATE para upsert en cada guardado.

    `playerid` INT UNSIGNED NOT NULL,

    `param`    INT UNSIGNED NOT NULL DEFAULT 0,
    `pos_x`    FLOAT NOT NULL DEFAULT 0.08,

4. Problemas resueltos durante el desarrollo

Problema 1 — Conflicto de símbolo al compilar

Causa: OnPlayerEditAttachedObject supera 31 caracteres, límite del compilador Pawn. Al hookear ese callback en dos archivos (marp_toy.pwn y marp_holster.pwn) el compilador truncaba el símbolo y generaba un conflicto de nombre duplicado.

Solución: El hook OnPlayerEditAttachedObject se dejó únicamente en marp_toy.pwn. Dentro de ese hook, cuando index == ATTACH_INDEX_ID_HOLSTER, se llama al forward Holster_OnEditAttached(...) definido en marp_holster.pwn. Build exitoso.

Problema 2 — Toy invisible al hacer /cadera

Causa identificada: La secuencia en CMD:cadera llama a SetHandItemAndParam(playerid, hand, 0, 0) que internamente ejecuta Weapon_RemoveFromPlayer → ResetPlayerWeapons. Esa llamada al motor de SA-MP genera un re-sync del personaje en el cliente que puede pisar el SetPlayerAttachedObject llamado inmediatamente después en el mismo tick del servidor.

Solución: Se reemplazó la llamada directa a Holster_Attach(playerid) por un timer de 100ms (SetTimerEx("Holster_AttachDelayed", 100, false, "i", playerid)). Lo mismo se aplicó al hook OnPlayerSpawn donde el spawn del cliente también resetea attachments.

Problema 3 — Toy invisible al spawnear / reloguear

Causa: OnPlayerSpawn se dispara en el momento exacto del spawn, antes de que el cliente termine de cargar el modelo del jugador. Cualquier SetPlayerAttachedObject llamado en ese instante puede perderse.

Solución: Mismo timer de 100ms aplicado al hook de spawn.
